# AGENTS.md

Guidance for AI agents and contributors working in this repository.

## What this repo is

CAD designs for the open-source OpenAgbot robots. All dimensions are in millimetres (mm).

| Robot | Description | Status |
| --- | --- | --- |
| `robot Bruut` | The small standard robot. Almost all files belong here. | Active |
| `robot Ekko` | Larger variant with bigger hub motors. | Folders prepared, no designs yet |

Related repos: [Bruut_OpenAgbot](https://github.com/JacobsFarm/Bruut_OpenAgbot) (software) and
[Bruut_OpenAgbot_Implements](https://github.com/JacobsFarm/Bruut_OpenAgbot_Implements) (implements).

## Repository layout

```
robot <Name>/
├── openscad/   parametric OpenSCAD design (source of the laser-cut, print and drill files)
└── freecad/    FreeCAD model, generated by Python scripts
```

Every robot gets the same two subfolders. Put new files in the robot they belong to. Never mix files of
different robots in one folder, and do not share `parameters.scad` between robots: Ekko gets its own copy.

### `robot Bruut/openscad/`

Layout, architecture and a description of every file are in `robot Bruut/openscad/README.md`. In short:
`config/parameters.scad` is the single source of truth, `parts/` feed `assemblies/`, and `assemblies/` feed the
`main_assembly_*.scad` entry points. Dependencies only point downwards, so never make a part include an assembly.

### `robot Bruut/freecad/`

FreeCAD 1.1 model of the real robot (2 fixed rear hub-motor wheels, 2 steered front wheels with a stepper on top).
The `.FCStd` is **generated**: change dimensions in `agbot_params.py` and rebuild with `run_in_freecad.py`, never
edit the `.FCStd` by hand. `agbot_params.py` mirrors `openscad/config/parameters.scad`: keep names and values in sync.
See `robot Bruut/freecad/README.md`.

## OpenSCAD standards

**File management**
- Single source of truth: share variables with `include <../config/parameters.scad>` at the top of every sub-file.
  Use `use <...>` to pull in modules from other files.
- Keep relative `include`/`use`/`import` paths intact when moving files; the folder structure inside `openscad/` is
  what makes them resolve.

**Parametric logic**
- Never hardcode critical dimensions. Always reference variables.
- Derive hole positions and other geometry from the main variables (for example `bracket_total_width / 3`). Do not
  redefine hole distances locally; pull them from the shared parameters.
- Respect existing variables such as `chassis_width`, `bolt_dia` and `bracket_total_width`.
- Keep bolt holes aligned with the existing drill-pattern lists in `parameters.scad`.
- Units are always millimetres.

**Coding style**
- Use English `snake_case` names for files, modules and variables.
- No citations or source tags in code (for example never `[cite: 122]`, no `source` tags).
- Short comments next to parameters are allowed and encouraged, explaining what the parameter does.
- Create a separate module for each new physical component.

**Design principles**
- Parts intended for DXF export are positioned exactly at Z=0 within their local module.
- Draw every module around its own origin with `center=true` for maximum symmetry.
- Use `for (i = [-1, 1])` for mirrored components such as wheels and side plates.
- Use a clearance variable for parts that overlap or fit into each other, never a literal.

**Production-ready output**
- Laser-cut parts: place flat in their own module at Z=0 and render with `projection(cut=true)` for DXF export.
- 3D parts such as tubes keep their volume, for drill templates or printing (STL).
- Use `$fn = 50` or higher for the final render of circles and holes.

## Working with an AI assistant

When asked to design in OpenSCAD, act as an OpenSCAD expert for the OpenAgbot project and follow the standards
above. In short: reuse the existing variables, one module per new part, bolt holes aligned with the drill-pattern
lists, and code without source or cite tags.

## Conventions

- Language in code and file names: English. Notes and READMEs may be Dutch or English.
- Large binaries (STL, STEP, renders) belong in the folder of the robot they are for.
- Do not commit generated scratch output (previews of experiments, `.FCBak` backup files).
